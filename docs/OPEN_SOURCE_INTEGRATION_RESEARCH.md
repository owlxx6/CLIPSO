# CLIPSO baseline verification and editing integration research

20 November 2026 · Windows local workflow · Engineering decision record

**Decision.** Keep the existing FFmpeg renderer, SQLite store and human review step. Three capabilities merit work in CLIPSO: replayable edit plans with quality receipts, pacing that protects quiet gameplay, and shot-aware facecam tracking that keeps the action visible. The immediate reliability task is smaller: surface decoder failures before caching signals or accepting a duplicate check. Quality gains for the three editing ideas remain hypotheses.

### Remaining defects and risks, ranked

1. **High — failed analysis decode can masquerade as empty media.** Against the fresh clone, an unavailable synthetic input produced zero buffers from `pcm_chunks` and zero frames from `gray_frames` with no exception. Both paths wait for FFmpeg and discard its status. The signature builder accepts an empty list. A transient decode failure can therefore weaken the cross-copy check if the subsequent render succeeds. Same-source overlap checks still run. Target the decoder and duplicate decision first. [Media readers](https://github.com/owlxx6/CLIPSO/blob/bc7260bfb94c218f3741bf29c5363dfef6017733/clipper/media.py#L82) · [Signature](https://github.com/owlxx6/CLIPSO/blob/bc7260bfb94c218f3741bf29c5363dfef6017733/clipper/dedup.py#L38)
2. **Medium — interrupted ingestion leaves a registered source.** Reproduced with an isolated SQLite store, a controlled successful media probe and a missing chat sidecar. Ingestion raised a file error and one source remained. An operator retry can register it again. Validate/stage sidecars before committing intake and compensate if promotion fails. [Ingestion](https://github.com/owlxx6/CLIPSO/blob/bc7260bfb94c218f3741bf29c5363dfef6017733/clipper/pipeline.py#L38) · [Source insert](https://github.com/owlxx6/CLIPSO/blob/bc7260bfb94c218f3741bf29c5363dfef6017733/clipper/db.py#L158)
3. **Medium — abrupt process loss can leave unregistered or obsolete files.** The fault tests cover Python/encoder exceptions. File promotion, SQLite commit and old-file cleanup span different storage systems. Hard termination between these operations can leave artifacts requiring reconciliation. This is a code-path finding; OS power loss was not simulated. A cleanup error after commit can also report failure even though the replacement is live. [Publication sequence](https://github.com/owlxx6/CLIPSO/blob/bc7260bfb94c218f3741bf29c5363dfef6017733/clipper/pipeline.py#L221)
4. **Medium — unbounded subprocess waits.** The main helper uses an argument list and explicit relative subtitle names in its working directory. Those choices protect Windows quoting. Blocking reads and process completion currently have no job deadline. A stalled decoder holds up the CLI or review action. [Process execution](https://github.com/owlxx6/CLIPSO/blob/bc7260bfb94c218f3741bf29c5363dfef6017733/clipper/media.py#L48) · [Filter construction](https://github.com/owlxx6/CLIPSO/blob/bc7260bfb94c218f3741bf29c5363dfef6017733/clipper/render.py#L104)
5. **Operational limits.** Source stat keys do not distinguish content replaced while preserving size and modification time. Candidate rematching uses overlapping moments and nearby peaks, which can be ambiguous on dense scenes. The synthetic suite cannot estimate the frequency of either condition or verify rights documentation, caption readability on real HUDs, music licensing or actual platform acceptance. [Cache identity](https://github.com/owlxx6/CLIPSO/blob/bc7260bfb94c218f3741bf29c5363dfef6017733/clipper/pipeline.py#L71) · [Matching](https://github.com/owlxx6/CLIPSO/blob/bc7260bfb94c218f3741bf29c5363dfef6017733/clipper/db.py#L181)

### WowClip · borrow time mapping and constrained tracking

The EDL updater checks a base version and validates the result, but accepts executable JavaScript transformations. CLIPSO should accept typed data operations for edits. The face tracker associates detections using overlap, center distance and optional SFace embedding similarity. The portrait planner splits at shot boundaries and builds face-centered rectangles. A full speaker crop can hide a GTA objective, minimap or action. Use geometry only in the streamer-camera region and preserve a gameplay pane. ## 5. Proposed three-agent architecture

**Highlight Hunter.** Keep existing source ingest, 0.5-second curves and per-streamer weights. Record signal contributions, nearest word IDs, optional reviewer-marked setup/payoff and protected intervals with the candidate. Calibrate on held-out VODs before adding signals. Test a low-resolution motion pass only around contested boundaries or strong chat peaks with little speech. Sparse motion can help distinguish a quiet chase from a menu. Treat cutscene flags as a review prompt.

**Video Editor.** A versioned `EditPlan` is the contract between a planner and deterministic rendering. Start with one continuous segment per platform so existing edits can be round-tripped before introducing internal cuts.

| Proposed field group | Representation and validation |
|---|---|
| Identity | Schema version, plan ID, monotonic revision, source ID and fingerprint, candidate ID, platform, effective config hash. Updates must name the base revision and source fingerprint. |
| Time | Integer source milliseconds, half-open intervals, ordered segments and explicit protected ranges. Derive the output clock cumulatively. Reject empty/out-of-bounds ranges, overlaps, cuts through protected spans and violations of platform duration. |
| Picture | Allowlisted layout, normalized bounded crop keyframes, shot ID, confidence, hold/fallback and bounded zoom (project cap 8%). Keep the gameplay safe region visible. Manual facecam overrides take priority. |
| Text and sound | Reference timed word IDs and hook text. Intersect each word with retained spans, map it to the output clock, then quantize for ASS. Use the existing loudness target. Carry source audio presence and expected output duration explicitly. |
| Publication | Read rights, campaign state and posted status from SQLite at execution. The planner cannot override them. Resolve media by source ID. Permit only known operations and approved output locations. |
| Receipt | Canonical plan hash, source fingerprint, renderer/encoder and effective settings, artifact digests, expected versus measured streams and durations, warnings and review status. Keep local paths and rights evidence private in externally shared summaries. |

For example, retaining source seconds [10, 14) and [16, 22) produces a 10-second export. A word at [17.0, 17.4) must appear at [5.0, 5.4). A protected payoff at [14.5, 15.5) makes that particular cut invalid. Use both examples as contract tests. Reject unknown schema versions before opening FFmpeg.

**Orchestrator.** Preserve the CLI and SQLite. A proposed job key combines source, plan revision and platform. Claim it in a short transaction, release the database during encoding, then recheck rights, duplicate evidence and posted status before promotion. Persist attempt count, lease expiry, stage location and receipt digest. Retry transient execution failures with a cap. Policy failures and missing signature evidence require review. On restart, reconcile staged artifacts and ledger entries before making an export available. Delivery remains a local review package followed by an explicit human post.

## 6. Controlled benchmark

Use the same authorized inputs, fixed source fingerprints and campaign settings for every arm. Start with at least three streamer/layout profiles and two VODs per profile where available. Use one VOD per profile for tuning, then freeze thresholds and evaluate on the other. Include quiet action, night scenes, music, no facecam, moving facecam, menus, rapid chat, silent stretches and cutscenes. Keep private footage, labels and renders outside Git. Report sample counts and missing categories.

1. **Ground truth.** Two reviewers independently mark source-time highlights, critical setup/payoff spans, and words/frames for sync and framing checks. Resolve disagreements before running the held-out comparison. Label the whole evaluation interval so recall has a denominator.
2. **Arms.** A = published baseline. B = A plus protected pacing. C = A plus facecam-region tracking. D = A plus plan, mapped captions and receipt. Freeze candidate IDs for editor comparisons. Evaluate Hunter changes separately on identical complete sources with the same one-to-one matching rule. Test combinations only after isolated effects are understood.
3. **Execution.** Fix FFmpeg build, resolution, frame rate, audio, model and encoder settings. Randomize arm order. Run one cold pass and three warm passes per resource comparison. Record analysis, rendering and validation separately. Compare libx264 and QSV as a separate factor. Use the same reference cut and quality settings appropriate to each encoder and record actual bitrates.
4. **Measurements.** Record wall time per source hour and per accepted clip. Process-tree peak RAM and CPU time. One-second CPU%, GPU engine utilization and GPU memory samples from Windows performance counters. Record unavailable counters as missing. Measure precision@10 and recall against the held-out marks, failure/retry counts, absolute word onset and offset error in ms, and the fraction of annotated frames retaining both facecam and critical gameplay. Report median/p95 and per-streamer results.
5. **Editorial outcome.** Review anonymized exports in randomized order. A clip is publishable when rights and disclosure gates pass, output decodes, the event is understandable, caption timing is acceptable and the reviewer would post it. Record numerator/denominator, blocking reason, active hands-on correction seconds and re-render count. Use paired clip-level differences, plus source-level uncertainty intervals when sample size permits.
6. **Proposed adoption gates.** Zero lost protected payoffs, policy bypasses, replaced posted exports or duplicate deliveries. Target at least 15% lower median correction time or 10 percentage points higher publishability, with no more than a two-point drop in highlight recall and no more than 20% higher median processing time. Proposed caption p95 error ceiling is 200 ms. Review uncertain or underpowered results before promotion. No external tool was benchmarked during this research.
